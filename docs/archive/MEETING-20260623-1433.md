PART 2 - MEETING AUDIT: what I changed in the viewer (plain English)
================================================================================
All of the below is shipped: commit 2376b83 on main, built clean, live on 3457.
These are viewer-side fixes. They make the app show the right numbers and behave
safely; they do NOT change the underlying database.

--------------------------------------------------------------------------------
CHANGE 1 - Re-sequenced samples no longer show up twice
--------------------------------------------------------------------------------
Plain English:
  5 TFMN4 samples were appearing twice in the sample list because they'd been
  sequenced under two different orders. The mutations query was joining on the
  sequencing-sample ID and getting two matching rows, so it produced phantom
  duplicate samples.
What I did:
  Collapsed those duplicate sequencing-sample rows down to one (grouped by the
  sequencing-sample ID) before the join, so each sample appears exactly once.
Result:
  TFMN4 went from 251 listed samples down to 246 distinct, with the metadata
  still resolving correctly. Verified directly against the database.
  (The real source-level dedupe is Natasha's item #3 above.)

--------------------------------------------------------------------------------
CHANGE 2 - Barcode charts now show their well positions
--------------------------------------------------------------------------------
Plain English:
  The amplicon/barcode charts were pulling well-position labels from the OLD
  Seqsamples table, which matched 0 of the 66 samples, so every chart was
  missing its well labels.
What I did:
  Switched that lookup to the authoritative Seq_samples table.
Result:
  All 66 amplicon samples now resolve their well positions (was 0 of 66).

--------------------------------------------------------------------------------
CHANGE 3 - Raw table browser hides deleted rows by default
--------------------------------------------------------------------------------
Plain English:
  Every table has a "deleted" flag. The Mutation Explorer already ignored
  deleted rows, but the raw "Database Tables" browser showed everything,
  including deleted junk. So browsing Experiments showed 51 rows when only 16
  are real, which reads as "wrong / duplicate data."
What I did:
  The raw browser (and CSV export) now hide deleted rows by default, with a
  "show deleted" toggle for auditing. The hide is always applied separately so
  an OR-filter can't accidentally surface deleted rows.
Result (what you SEE now vs before):
  Samples:      572 live   (was showing 1253)
  Seq_samples:  885 live   (was showing 1690)
  Experiments:   16 live   (was showing 51)

--------------------------------------------------------------------------------
CHANGE 4 - Legacy duplicate tables are tagged and pushed down
--------------------------------------------------------------------------------
Plain English:
  The duplicate/legacy tables (Seqsamples, Seqorders, dgoA_alleles_old) were
  sitting in the table list right next to the real ones, inviting someone to
  pick the wrong, partial table.
What I did:
  Tagged them with a dimmed "legacy" badge and sorted them to the bottom of the
  sidebar. They're still reachable, just clearly de-emphasized.
Result:
  The canonical table is now the obvious choice. (Retiring them for real is
  Natasha's item #6.)

--------------------------------------------------------------------------------
CHANGE 5 - Numeric filters stop silently returning nothing
--------------------------------------------------------------------------------
Plain English:
  If you typed a non-number into a filter on a numeric column (e.g. "abc" in a
  count field), the query silently returned zero rows with no explanation.
What I did:
  A non-numeric value on a numeric column now skips that condition instead of
  zeroing out the results (applies to =, IN, and BETWEEN filters).
Result:
  No more confusing "empty table" from a typo in a filter.

--------------------------------------------------------------------------------
CHANGE 6 - CSV export is safer in Excel
--------------------------------------------------------------------------------
Plain English:
  When you open a CSV in Excel/Google Sheets, a cell that starts with =, +, -,
  or @ can be interpreted as a live formula (a known spreadsheet-injection
  risk). Our exports could carry such values.
What I did:
  Cells starting with those characters now get a leading quote so they're
  treated as text, and the file uses proper Windows-style line endings.
Result:
  Exports are safe to open in any spreadsheet and read identically.

--------------------------------------------------------------------------------
CHANGE 7 - API hardened against bad query strings
--------------------------------------------------------------------------------
Plain English:
  The data and export endpoints didn't sanity-check the page/page-size/limit
  numbers from the URL. A bad value could break the query or pull an unbounded
  amount of data.
What I did:
  Clamped page, page size, and export limit to sane bounds, and confirmed all
  table and column names are whitelisted against the real schema before they
  ever touch SQL (so the query surface is injection-safe).
Result:
  The app degrades gracefully on malformed/hostile requests instead of erroring
  or over-fetching.

--------------------------------------------------------------------------------
CHANGE 8 - Build/lint cleanup
--------------------------------------------------------------------------------
Plain English:
  Cleaned up the build so it passes with zero errors. One real type-smell fixed;
  a noisy React advisory rule documented and downgraded to a warning because the
  remaining cases are legitimate, standard React patterns (not bugs), and
  rewriting working render logic right before the meeting wasn't worth the risk.
Result:
  TypeScript clean, lint clean (0 errors), production build clean (all 11
  routes), app live and healthy on 3457.
